# 04：协作群设置

状态：实施中，功能及定向验证已通过，等待全量结果与独立审查。对应 [04 工单](../issues/zcode-local/04-group-collaboration-settings.md)。起点 `901fdb2f`，分支 `3.16.2-local.1`，日期 2026-10-21。

## 用户行为

在 Local 的机器人设置中打开飞书或 Lark 机器人，新增「PM 群协作」设置卡。选择已有绑定群、一个 PM、执行者与职责、授权用户及固定本机项目，然后启用并保存。不同群独立保存，修改机器人显示名不改变职责。

没有可信身份时，点击对应机器人的核验按钮，在群内原生 @ 该机器人并发送界面生成的十分钟有效命令，再刷新设置。核验只能由该机器人当前绑定用户完成；正文中的名字或手填平台 ID 不能代替。核验命令不创建任务。若当前群尚未接入该机器人，成功核验复用既有群激活入口；之后关闭原群开关，普通消息不会重新打开它。

飞书用户 open_id 属于单应用，跨机器人确认同一用户使用 Provider 事件中的 tenant_key 与 union_id，各机器人仍保存自己的应用内身份；缺失证明时保持未核验。依据：[飞书身份说明](https://open.feishu.cn/document/platform-overveiw/basic-concepts/user-identity-introduction/introduction)。

有群输入正在接收、任务在办或运行事实无法确认时，关键设置拒绝保存并显示原因。无变化保存不增加版本；有效变更递增版本，旧窗口不能覆盖，原群卡片的旧授权会失效。群请求使用保存的固定项目，不能通过群内 workspace 命令临时切换。

## 实现与兼容

共享协议、配置所有者与设置界面分别进入三个托管模块，接口、示例、契约测试及模块清单齐备。UI 经 hook 调用现有 Bot 服务 RPC；宿主没有 Local 能力时不显示设置卡。

配置由协作服务唯一写入实际业务根 `.zcode/local/v1/collaboration.json`，version 1，异步短锁及私有原子写入。配置带 expectedRevision；机器人身份由可信 Provider 入站填写，界面仅提交选项 ID。旧版以项目根路径保存的权限沿用现有规范化规则。官网 Bot v3 与 SQLite 格式没有新增字段。

同群接收调用令牌在锁内登记，处理函数在锁外只执行一次，finally 移除令牌；不同 Host 共享可见。记录不含正文，不表示任务已受理，不是新的执行队列。崩溃遗留记录保持状态未确认，后续 12 负责核对恢复。

## 本票边界

本票交付可信的群配置基础。PM 派单、执行者回报、原需求用户归属归 05；无动作静默、选人卡片、串行执行、恢复依次由后续工单实现。未启用群与非 Local 宿主沿用既有行为。

02 已签名候选仍是 02 源码，本票没有更新该候选、安装替换应用或重启日常机器人。未来候选与日常安装按后续工单推进，不将旧包称为已经包含 04 的新版本。

复验入口：固定 Node 24.14.0 与 pnpm 10.33.2 后，从仓库运行 `pnpm test:local-collaboration-ui`。默认建立临时隔离数据，结束后清理；需保留证据时设置 `ZCODE_TEST_ARTIFACT_DIR` 到仓库外专用目录。
