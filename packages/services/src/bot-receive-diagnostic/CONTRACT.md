# bot-receive-diagnostic

空闲观察补正：idleness 阶段仅增加固定拒绝原因枚举与受限的已核对任务计数，沿当前调用传递观察上下文，不建立全局当前消息。沿用原 scope、HMAC、时限、数量、默认关闭与失败隔离；不记录原 task ID、路径、正文或异常文本。

18 经用户批准的一次本机观察能力。该 owner 只管理有限元信息写入，不拥有配置授权、消息接收或执行状态，不提供业务判定、RPC、重放或上传能力。Bot 服务和 Feishu SDK 只在原事件边界旁路调用 record；原协作及任务 owner 不依赖观察结果。

不变量：

- 仅 Local 能力和显式环境变量 `ZCODE_LOCAL_RECEIVE_DIAGNOSTIC_FILE` 同时开启时读取一次 schema 1 严格请求；未配置/官网不读写。不能验证 POSIX 所有权的平台保持关闭，业务照常运行。
- 请求所在目录须当前用户所有、0700 且为规范无链接路径；请求须当前用户所有、0600、单硬链接普通文件且最多 4096 字节。botId/chatId 精确匹配，expiresAt 最多未来 30 分钟，maxRecords 为 1–200，salt 为本次独立 32 字节随机值。
- 单个目录以 claimed 独占领取，events.jsonl 独占创建且 0600，不覆盖或跟随已有文件；多 Host 或重建不能续写。有效期同时用绝对与单调时钟约束，不能按超时释放任何业务 owner。
- 既有 WebSocket owner 连接指定 bot 后，可记录不含群/消息数据的 connection/ready；此条只需 bot 匹配且无 chatId，供核对观察器已就绪。其余消息必须 bot/chat 均精确匹配，生命周期记录也占额度，不新增连接或抢锁。
- 只序列化固定 schema、时间/序号、分离命名空间的消息/发送者 HMAC、固定阶段/结果及白名单事实。原始 scope、正文、名称、路径、异常、header 和凭据不能进入输出；未知字段/枚举不序列化。不启用原服务 debug。
- record 不等待 IO；有限元信息缓冲最多 200 条，写入顺序与调用顺序一致，数量上限与到期均停止输出。任何读取/写入失败只关闭诊断，不向业务抛错。dispose 拒绝新记录，等待已启动读取/写入并关闭句柄。
- 请求、claimed 和输出都是本机私有一次材料，不进入 Bot v3 或 Local ledger；本能力不删除它们，不重试失败写入，不重发事件。捕获不到过去未记录的原始事件，空日志不能单独证明平台未推送。
